1. Overview

This document provides step-by-step instructions for deploying the {{ project_name }} system to a production environment. It covers infrastructure setup, environment configuration, database migrations, CI/CD pipeline, monitoring, and rollback procedures.

3. Architecture Overview

The production architecture follows a 3-tier deployment model:

  • Load Balancer — Nginx / AWS ALB distributes traffic across application instances
  • Application Tier — Docker containers running the backend API (auto-scaled)
  • Data Tier — Managed PostgreSQL (RDS / Cloud SQL) + Redis cluster
Internet → CloudFlare CDN → Load Balancer (Nginx)
                                    ↓
                     ┌──────────────────────────┐
                     │   App Container Pool      │
                     │  (API Instances × N)       │
                     └──────────────┬────────────┘
                                    ↓
                     ┌──────────────────────────┐
                     │  PostgreSQL (Primary)      │
                     │  PostgreSQL (Read Replica) │
                     │  Redis Cluster             │
                     └──────────────────────────┘

5. Database Setup & Migrations

5.1 Initial Database Setup

# Connect to PostgreSQL
psql -h $DB_HOST -U postgres

# Create application database and user
CREATE DATABASE appdb;
CREATE USER appuser WITH ENCRYPTED PASSWORD 'strong_password';
GRANT ALL PRIVILEGES ON DATABASE appdb TO appuser;
\q

5.2 Running Database Migrations

# Run Alembic migrations
cd /app
alembic upgrade head

# Verify migration status
alembic current

# Seed initial data (if applicable)
python scripts/seed_data.py

6. Application Deployment

6.1 Build Docker Image

# Build production image
docker build -t {{ project_name | lower | replace(" ", "-") }}:latest \
  --build-arg BUILD_ENV=production .

# Tag with version
docker tag {{ project_name | lower | replace(" ", "-") }}:latest \
  registry.example.com/{{ project_name | lower | replace(" ", "-") }}:v1.0.0

# Push to registry
docker push registry.example.com/{{ project_name | lower | replace(" ", "-") }}:v1.0.0

6.2 Deploy with Docker Compose

# Pull latest images
docker-compose -f docker-compose.prod.yml pull

# Start services (zero-downtime rolling update)
docker-compose -f docker-compose.prod.yml up -d --remove-orphans

# Check status
docker-compose -f docker-compose.prod.yml ps

# View logs
docker-compose -f docker-compose.prod.yml logs -f --tail=100 app

6.3 Nginx Configuration

server {
    listen 443 ssl http2;
    server_name {{ project_name | lower | replace(" ", "-") }}.example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    ssl_protocols       TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    gzip on;
    gzip_types text/plain application/json application/javascript text/css;

    location /api/ {
        proxy_pass         http://localhost:8000;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 30s;
        proxy_connect_timeout 10s;
    }

    location / {
        root /var/www/html;
        index index.html;
        try_files $uri $uri/ /index.html;
    }
}

# Redirect HTTP → HTTPS
server {
    listen 80;
    server_name _;
    return 301 https://$host$request_uri;
}

  • Logs — ELK Stack (Elasticsearch + Logstash + Kibana) or CloudWatch Logs
  • Alerting — PagerDuty / OpsGenie for P1/P2 incidents; Slack for P3/P4

  • APM — Datadog or New Relic for distributed tracing

10. Rollback Procedure

Rollback must be executed within 15 minutes of a critical production issue. 
# Step 1: Identify the previous stable image tag
docker ps -a | grep app

# Step 2: Pull previous stable version
docker pull registry.example.com/{{ project_name | lower | replace(" ", "-") }}:v0.9.0

# Step 3: Update docker-compose.prod.yml with previous image tag
# Then redeploy
docker-compose -f docker-compose.prod.yml up -d

# Step 4: Verify rollback
curl -s https://{{ project_name | lower | replace(" ", "-") }}.example.com/health

# Step 5: Roll back database migration (if needed)
alembic downgrade -1

# Step 6: Notify stakeholders of rollback event
